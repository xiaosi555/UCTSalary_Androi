UCT salary（工资APP）需求说明书

工时记录 · 工资核算 · 多用户 · 按周期配置　——　Web 版功能基线 与 Android 原生实现规格

文档版本 v1.0基线：工资APP_日历颜色修正版.html目标平台：Android 8.0+（API 26）技术栈：Kotlin · Jetpack Compose

1. 文档说明

1.1 目的与范围

本文档完整描述“UCT salary”工时/工资记录应用的业务需求，作为 Android 原生版本（工程 UCTSalary）的开发、测试与验收依据。需求来源于现有 Web 单文件版本（以下称“基线版”），文档中的所有规则、公式、默认值均已与基线版实际运行结果逐项核对（见第 11 章验收用例，数值由基线版实测生成）。

1.2 术语

术语含义
工资周期（周期）上月 16 日 ～ 本月 15 日。例如 09.16–10.15。
周期键（cycleKey）6 位字符串 YYYYMM，取周期结束月。09.16–10.15 的周期键为 202610。日期 d 的周期键：日 ≥ 16 则为次月，否则为当月。
设置版本（SettingsVersion）某周期起生效的一份完整设置快照（工资、扣除、五险比例、补贴、考勤周期）。键 from 为生效周期键，最早版本为 000000。
时薪（hs）月基本工资 ÷ 21.75 ÷ 8，全程保留双精度，不提前四舍五入。
班次类型白班、夜班、中班、休息、平时加班、周末加班、调休加班、节假日加班（记录中另有早班、晚班，用于统计与导入）。
分段加班一条记录的加班工时拆成最多两段，每段独立倍数。
当前用户应用在任一时刻只操作一个用户的数据；各用户数据完全隔离。

2. 产品概述

定位：面向按小时计薪、存在加班的产线/工厂员工的离线记账工具。用户逐日记录班次与加班，应用按“基本工资 + 加班 + 补贴 − 五险一金 − 个税”实时核算当期收入，并提供日历、统计图表、工资条核对、CSV 数据备份。

核心价值：① 一天记一笔，随手可记（快捷标签）；② 分段加班、夜班周五/周日特例自动处理；③ 工资参数按周期版本化，历史月份不受后续调薪影响；④ 全部数据本地保存，可一键导出为单个 CSV。

用户：单设备可建多个用户（如家人），数据互相独立，记录时可一次同步给多个用户。

3.2 导航规则

  • NAV-1 采用“进入路径栈”：进入新页面时把当前页压栈；返回（页面左上角按钮或系统返回键）弹栈回到真实上一页，不写死返回目标。栈为空时回首页。
  • NAV-2 返回优先级：弹窗/底部面板 → 页面栈。
  • NAV-3 页面进入使用横向滑入 + 淡入动效，返回使用反向滑入；弹窗使用遮罩淡入 + 卡片上浮；系统开启“减少动画”时关闭动效。
  • NAV-4 带周期的跳转（统计 → 设置）：目标设置页的“配置周期”预置为统计页当前所看周期；从设置菜单进入则预置为今天所在周期。离开设置页后恢复为今天所在周期。

4. 功能需求

优先级：P0必须　P1重要　P2增强。

4.1 多用户（FR-USER）

编号需求验收要点
U-1 P0首次启动自动创建默认用户：id=u1，昵称“我”，性别“保密”。全新安装即可使用。
U-2 P0用户字段：id、昵称（必填）、头像（可空，data URL）、性别（男/女/保密）、联系电话、备注。新用户 id = u + 当前毫秒时间戳的 36 进制。昵称为空时保存提示“请输入昵称”。
U-3 P0切换用户：首页头像 → 列表（当前用户高亮并标注“当前”）→ 点击他人即切换；点击当前用户仅关闭弹窗；弹窗内有“管理用户”入口。切换后首页、日历、统计、设置全部显示新用户数据。
U-4 P0数据隔离：记录、工资/补贴/扣除版本、快捷记录、主题、明细项、汇总显示开关、工作日、正常工时、考勤周期均按用户独立。A 用户修改不影响 B 用户。
U-5 P0删除用户：至少保留 1 个用户（仅 1 个时不显示删除）；需二次确认“其全部数据将被清除且无法恢复”；删除当前用户后自动切换到列表第一个用户。删除后该用户全部存储键清空。
U-6 P1头像：从相册选图，居中裁剪成正方形并缩放到 160×160，JPEG 质量 0.85，存为 data:image/jpeg;base64,…；无头像时显示昵称首字、主题色浅底圆形。—
U-7 P0用户切换需原地完成（不重启应用），并有切换动效：当前页淡出 → 新用户首页滑入 + 头像弹跳 + 顶部提示“已切换到「昵称」”。切换耗时 < 0.3 秒（含动画）。

4.2 首页（FR-HOME）

  • H-1 顶部背景图区域（主题背景，离线时回退为主题色渐变），左上标题“UCT salary”，右上用户头像（点击切换用户）与设置图标。
  • H-2 收入区：标题“MM.16 - MM.15收入”（今天所在周期，基线版此处为静态文本，Android 版改为动态）+ 眼睛开关；大字号显示“当月实际收入”（= 该周期统计页“本月收入”，即净收入）；下方“加班时长 / 加班收入”（今天所在周期）。眼睛关闭时三处数值分别显示 ****.**、****、****.**。
  • H-3 白色功能卡片：日历、统计、签到三个入口；“记加班”主按钮；快捷记录标签横向滚动 + 右侧“设置”（虚线边框，闪电图标）。
  • H-4 快捷标签区文案：关闭展示时“快捷记录展示已关闭”；无数据时“暂无快捷记录”；标签文本 = 名称 + “•” + 加班小时 + “h”。

4.3 工时记录（FR-REC）

入口：首页“记加班”（日期=今天，新增）、日历单元格（有记录=编辑，无=新增）。

编号需求
R-1 P0表单字段：用户多选（默认全选；至少选 1 个，仅剩 1 个时不可取消）、日期、星期（自动）、基础工时（隐藏，自动）、加班倍数（1.5 / 2.0 / 3.0）、加班工时（文本）、拆分加班（可选）、班次类型（8 选 1）、备注、预计薪资（实时）。
R-2 P0基础工时：休息 → “休”；周末加班/节假日加班 → “0”；其余班次 → 该日星期属于“工作日集合”则取“正常工时”（默认 8），否则 0。
R-3 P0新增默认值：班次=夜班，加班工时=3，倍数=1.5，日夜班=用户默认日夜班（快捷设置里配置，默认夜班）。随后应用夜班特例（R-6）。
R-4 P0切换班次联动：休息 → 加班 0；周末加班/节假日加班 → 加班 11、倍数 2.0；其他 → 加班 3，且若上一个班次是周末/节假日加班则倍数恢复 1.5。切换后重算基础工时、备注、预计薪资。
R-5 P0备注自动生成（在班次、日期、加班工时变化时覆盖备注）：加班工时 ≤ 0 → “未加班”；否则 前缀+工时+小时，前缀为班次名（仅周末加班/节假日加班）否则为“加班”，如“加班3小时”“周末加班11小时”。分段保存时备注固定为 5h为2倍，6h为1.5倍（每段 {小时}h为{倍数}倍，用“，”连接）。
R-6 P0夜班特例（班次=夜班时）：
• 周五：倍数强制 2.0。
• 周日：新增/切到夜班/改日期时加班工时=11（未展开分段时仍按所选单一倍数，默认 1.5）；展开拆分且两段为空时自动预置“第一段 5h×2 倍 + 第二段 6h×1.5 倍”，总工时 11。
• 周五展开拆分且两段为空：第一段 = 总工时（缺省 3）×2 倍，第二段空。
R-7 P0拆分加班：默认折叠（摘要“默认按单一倍数计算”）。展开后有“第一段工时/倍数、第二段工时/倍数”（倍数可选 1.5/2/3）。
• 展开时若两段为空：夜班周日→5@2 + 6@1.5；夜班周五→总工时@2；其他→总工时@当前倍数。
• 修改任一段：加班总工时 = 两段之和（格式化）。
• 直接修改总工时：第二段 = 总工时 − 第一段；若总工时 < 第一段则先缩短第一段。
• 有效分段需满足：面板展开、至少一段 > 0、两段之和 = 总工时（容差 1e-6），否则视为无分段。
• 保存时若已展开但分段无效且加班 > 0，提示“展开分段后，请填写分段工时，并确保分段工时合计等于原加班工时。”并拒绝保存。
R-8 P0预计薪资 = 基础工时×hs + 加班工资；hs 取该日期所在周期的设置版本；休息为 ¥0；金额按 fmtMoney（两位小数，整数去掉 .00）。
R-9 P0保存：记录结构 {shiftType, dayNight, hours, otHours, otRate, otSegments|null, remark, salary}；对所有选中用户写入同一日期（覆盖同日旧记录）；保存后刷新日历、统计、首页汇总。未选日期提示“请选择日期”。
R-10 P0删除：仅编辑已有记录时显示“删除”；点击先关闭编辑弹窗再弹出确认“确认删除 / 确定要删除该日期的工时记录吗？删除后无法恢复。”；确认后删除并刷新。
R-11 P1加班倍数标签旁有“去设置”图标，点击关闭弹窗并进入工资设定页（周期=该记录日期所在周期）。
R-12 P2加班工时输入框：获得焦点且内容为 3 或 3.0 时清空；失去焦点且为空时恢复为 3。

4.4 快捷记录（FR-QUICK）

  • Q-1 默认三条：“夜班11h”(blue, 3h, 1.5)、“白班11h”(orange, 3h, 1.5)、“周末11h”(orange, 11h, 2.0)。字段：名称、颜色类型(blue=夜班/绿色标签、orange=白班/橙色标签)、加班小时、加班倍数。
  • Q-2 点击首页标签 = 记录今天：班次推断——记录自带 shiftType 优先；名称含“周末”→周末加班；type=blue→夜班；否则白班。日夜班：夜班→“夜班”，白班→“白班”，其他→用户默认日夜班。基础工时按 R-2；加班工时取标签值。
  • Q-3 夜班特例同样适用：夜班周五倍数改 2.0；夜班周日且加班 > 0：前 min(5, 加班) 小时 2 倍，剩余 1.5 倍成两段，备注为分段备注，否则备注“加班{h}小时”。
  • Q-4 若今天已有记录，先弹确认“当天已有工时记录 / {日期} 已存在记录。是否用【名称】覆盖当天原有工时数据？”（覆盖记录/取消）；成功后提示“记录成功 / 已将【名称】记录到 {日期}，工时及工资已更新。”。
  • Q-5 设置页：“快捷记录在首页展示”开关、“白夜班”默认选择（白班/夜班）、卡片列表（徽标夜班/白班 + 名称 + “加班小时数/加班倍数”+ 编辑）、新增快捷记录。编辑弹窗：班次名称（默认“新班次8h”）、颜色类型、加班小时数（默认 3）、加班倍数（默认 1.5）；保存空名称取“自定义班次”，倍数空取 1.0。副标题显示“N个班次”。

4.5 日历与收支汇总（FR-CAL）

  • C-1 展示一个工资周期的日格：自 16 日起至次月 15 日，7 列（日～六），首行按 16 日的星期留空位；格高 56dp。顶部：上一周期按钮（文字“{上一周期起始月的前一月}月”）/ 周期标题“MM.16-MM.15” / 下一周期按钮（“{结束月+1}月”）；右侧切换“总/细”。
  • C-2 单元格内容：左上日号；有记录时右上显示加班徽标；总模式右下角显示当日合计，细模式在中间多显示基本工资（灰色小字）。休息显示“休”。
  • C-3 颜色规则（“日历颜色修正”基线）：
    • 今天：2px 主题色边框 + 主题色 20% 底色。
    • 夜班（日夜班=夜班且非休息、非今天）：边框为主题色。
    • 徽标底色：默认主题色；休息灰（#9CA3AF，金额灰色）；周末加班橙（#F97316）；节假日加班红（#EF4444）；金额文字同色系。
    • 徽标文字色：倍数恰为 2 时为近黑（#111827），其余为白色。分段记录显示多段小时数（空格分隔），每段按各自倍数着色。
    • 单段记录徽标显示加班小时（休息不显示徽标）。
  • C-4 点击日格：有记录进入编辑，无记录进入新增（日期=该格）。
  • C-5 收支汇总（日历页下方）：六项网格 + 合计。
    基本工资(+)、加班工资(+)、夜班补贴(+，可隐藏)、餐补=伙食补贴(+，可隐藏)、应纳税所得额(−，可隐藏)、个人五险(−，可隐藏)。眼睛按钮切换显示；隐藏项数值灰色删除线且不计入合计。合计 = Σ(可见项 符号×数值)。开关状态按用户持久化。标题行有“查看统计”按钮跳统计页（加班统计标签）。
    应纳税所得额 = 当前周期“扣除 → 个人所得税(月)”设置值，与设置同步。

4.6 统计（FR-STATS）

顶部：返回、标题“统计”、周期导航（上一周期月份 / “MM.16-MM.15” / 下一周期月份）、四段标签。进入统计页默认定位到今天所在周期（或最近一次导入数据所在周期）并选中“加班统计”。

A. 加班统计

  • S-1 总览：加班收入(元)、已加班(天)、已加班(小时)。仅统计“加班小时>0 且 加班工资>0”的记录。
  • S-2 汇总：按倍数（升序）列出：倍数方块“N倍/工资”、“{hs×倍数}元/小时”、金额、小时、天数，下方占比进度条（占加班收入百分比）。分段记录按每段倍数分别累计小时与金额，天数各+1。
  • S-3 加班收入分析：环形图（各倍数金额），中心显示加班收入合计与“加班收入”；无数据显示“暂无加班数据”。
  • S-4 加班时长统计：按“单日加班时长”分组的柱状图（天数），横轴 “Nh”。
    S-5 加班日期统计：周期内每天一根柱（加班小时），无加班为灰色低柱，横轴为日号。

B. 记月工资

  • S-6 顶部“本月收入”大数字 = 净收入。三个可折叠面板：基本项目（默认展开：基本工资、加班工资）、补贴项目（默认折叠）、扣除项目（默认折叠，有各自显示开关）。每行可点击跳转到对应设置页（NAV-4）。
  • S-7 补贴项目行：仅列出“启用且金额>0”的补贴；按日补贴副标题“{金额}元/天 × {天数}天”，按月补贴副标题“按月”；无项目时显示“暂无补贴项目（点击去设置）”。
  • S-8 扣除项目行：五险个人、公积金个人、个人所得税（均显示为负）；每行右侧眼睛可单独隐藏（仅影响列表显示，不影响扣除合计与净收入）；全部隐藏显示“当前没有启用显示的扣除项目”。开关按用户持久化。
  • S-9 底部固定栏（仅本标签）：收入(gross)、扣除(−)、本月收入(net)。

C. 班次统计

  • S-10 六格：早班、中班、晚班、白班、夜班、休息，显示“N天”；点击弹出“{班次} - 班次明细记录”表（序号、日期、星期、工时、基本工资、加班工资、当日合计、班次、备注），无记录显示“该周期内暂无【班次】记录”。
  • S-11 班次分布环形图（中心“N天/班次天数”），无数据显示“暂无班次数据”。

D. 工资条

6. 计算公式

6.1 格式化

  • fmtMoney(n)：n.toFixed(2)（按二进制精确值四舍五入，等同 BigDecimal(n) HALF_UP）；结果为 -0.00 时取 0.00；以 .00 结尾则去掉“.00”。例：267.96、1811.41、3730、0。
  • formatHourNumber(n)：数值转字符串（整数不带小数点，如 3、2.5）。

6.2 时薪 hs

d  = base / 21.75 / 8                      // 高精度，不取整
st = hourSalaryExact ?: hourSalary          // 版本存档值
if st ≤ 0 → hs = d
if d > 0 且 st ≠ d 且 |st−d| < 0.005 且 st 恰为两位小数 → hs = d   // 视为被四舍五入后的存档值，还原
否则 hs = st

例：base=3730 → hs = 21.436781609195403；base=5000 → 28.735632183908045。

6.3 单日工资 recPay

hours == "休"            → base=0, ot=0, total=0
base = (hours 数值 或 0) × hs
ot   = otSegments 非空 ? Σ(seg.hours × hs × seg.rate(缺省1)) : otHours × hs × (otRate 缺省1)
total = base + ot

6.4 周期

cycleKeyOfDate(d) = (day ≥ 16 ? 次月 : 当月) 的 YYYYMM
周期(key=YYYYMM) = [上月16日, 当月15日]；上月：month==1 → 去年12月
getCycleRecordKeys = 周期内全部有记录的日期（升序）

6.5 补贴

subsidyDays(item) = mode=="daily" ? (days>0 ? days : 周期结束月的自然日数) : 0
subsidyValue(item) = !enabled ? 0 : (mode=="daily" ? amount × subsidyDays : amount)

例：夜班补贴 5 元/天 × 15 天 = 75；8 元/天 × 当月天数（11 月 30 天）= 240。

6.6 扣除

五险个人 = 社保基数 × (养老+医疗+失业+工伤+生育 个人比例之和) / 100     （按该周期版本）
五险单位 = 社保基数 × (五项单位比例之和) / 100
公积金个人 = 公积金基数 × 缴存比例 / 100         （单位相同）
个税 = 个人所得税(月)设置值

6.7 统计与收入

otIncome   = Σ 有加班记录的 ot            （otHours>0 且 ot>0）
basicTotal = 基本工资 + otIncome
subTotal   = Σ 启用且>0 的补贴值
gross      = basicTotal + subTotal
totalDeduct= 五险个人 + 公积金个人 + 个税        （与显示开关无关）
net        = gross − totalDeduct                  → 首页“当月实际收入”、统计“本月收入”
收支汇总合计 = base + ot + (夜班补贴) + (餐补) − 应纳税所得额(=个税设置值) − 五险个人    （仅计入可见项）

std_days标准天数22（固定）

  • 生效周期接受 起始/最早/0、202610、2026-10、2026年10月；补贴行引用不存在的周期时跳过。
  • 主题背景/主题色必须在内置列表内才应用；考勤周期 0–30；正常工时 1–24；工作日仅接受周一～周日。
  • 当日工资按导入后各周期设置重新计算，不信任文件中的值。
  • 导入确认摘要示例：“将导入到当前用户「X」：· 工时记录 N 条（新增 a，覆盖 b）· 周期设置 … · 周期补贴 … · 快捷记录 … · 明细项 … · 其他设置 … · 跳过无法识别的 k 行”。

10. Android 实现方案

10.1 技术选型

  • Kotlin 2.0、Jetpack Compose + Material 3、单 Activity；minSdk 26 / targetSdk 34。
  • 状态：AppViewModel（Compose 快照状态）+ 纯函数计算层；导航用自有页面栈 + AnimatedContent（与 NAV-1 一致）。
  • 存储：SharedPreferences + kotlinx.serialization（键名/结构同基线版）。
  • 图片：Coil 加载背景图；图表使用 Compose Canvas 自绘（环形图、柱状图），无第三方图表依赖。
  • 文件：Storage Access Framework（CreateDocument / OpenDocument）读写 CSV，无需存储权限。
